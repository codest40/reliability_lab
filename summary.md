# 1. Observability Coverage

| Area | Metrics / Signals | What It Tells Us |
|---|---|---|
| **HTTP** | Requests, duration, errors, responses, in-progress | Client demand, latency, errors, and current request load |
| **Dependency** | Requests, duration, errors, timeouts, connection errors | Health and performance of Service B from Service A's perspective |
| **Workers** | Total, busy, available | Processing capacity and worker saturation |
| **Queues** | Size, capacity, utilization, rejections, wait duration | Backlog, queue pressure, admission capacity, and queue latency |
| **Retries** | Retries, attempts, exhausted, delay | Retry behavior and additional traffic generated by retries |
| **Circuit Breaker** | State, transitions, rejections, opens, probes, probe success/failure | Dependency protection, instability, and recovery behavior |
| **Recovery Probes** | Total, success, failure, duration | Whether a dependency is actually recovering and ready for traffic |
| **Bulkhead** | Capacity, active requests, rejections | Per-workload capacity isolation and resource contention |
| **Dependency Health** | Health, pressure state | Whether the dependency is alive and whether it is under sustained pressure |
| **Application** | Processed, saved, invalid | Business-level outcomes and application correctness |
| **Slo** | Availability, latency objective, error budget

# 2. Reliability Concepts We Can Calculate

The current implementation provides enough data to derive several important SRE reliability indicators.

| Reliability Concept | Status | Derived From | What It Tells Us |
|---|:---:|---|---|
| **SLI** | ✅ | Requests, errors, latency, dependency metrics | Quantitative measurement of service reliability |
| **SLO** | ✅ | SLI + defined target | Reliability objective the service is expected to maintain |
| **SLA** | ✅ Conceptually | SLO + external commitment | Reliability commitment made to users/customers |
| **Error Budget** | ✅ | SLO target + measured reliability | How much unreliability is acceptable before the SLO is violated |
| **Error Rate** | ✅ | Errors / total requests | Percentage of requests that fail |
| **Availability** | ✅ | Successful requests / total requests | Percentage of requests successfully served |
| **p95 Latency** | ✅ | `http_request_duration_seconds` histogram | Latency experienced by 95% of requests |
| **p99 Latency** | ✅ | `http_request_duration_seconds` histogram | Tail latency experienced by 99% of requests |
| **Dependency p95/p99** | ✅ | `dependency_request_duration_seconds` | Tail latency introduced by Service B |
| **Queue Pressure** | ✅ | Queue size / capacity | How close the system is to exhausting queued capacity |
| **Worker Saturation** | ✅ | Busy workers / total workers | How much processing capacity is currently consumed |
| **Dependency Failure Rate** | ✅ | Dependency errors / dependency requests | Reliability of Service B from Service A's perspective |
| **Retry Rate** | ✅ | Retry counters / request counters | How frequently operations require retries |
| **Retry Amplification** | ✅ | Dependency attempts vs original requests | How much additional dependency traffic retries create |
| **Circuit-Breaker Impact** | ✅ | Open events, state, rejections, transitions | How often dependency protection activates and affects clients |
| **Throughput** | ✅ | Request counters / rate over time | How much work the system is successfully processing |
| **Saturation** | ✅ | Workers + queues + dependency pressure | Whether system capacity is approaching exhaustion |
| **MTTD** | ⚠️ Additional timestamps needed | Incident start + detection timestamps | How quickly an incident is detected |
| **MTTR** | ⚠️ Additional timestamps needed | Incident start + recovery timestamps | How quickly the system recovers from an incident |
| **MTBF** | ⚠️ Additional failure history needed | Failure and recovery events | Average operating time between failures |
| **MTTF** | ⚠️ Additional lifecycle data needed | Failure-event start/end history | Average time until a defined failure occurs |
